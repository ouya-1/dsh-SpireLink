# 安装与使用手册 —— 写给「大肥鱼」

> 这份文档是给**要自己上手玩《杀戮尖塔》的 AI agent（大肥鱼 / DeepSeek）**看的。
> 只讲两件事：**怎么把它装起来**，**装起来之后怎么打**。
> 字段级契约看 [MCP-返回格式.md](MCP-返回格式.md)，每个界面能做什么看 [界面清单.md](界面清单.md)，踩坑清单看 `skill/spirelink/references/recovery.md`。

---

## 0. 一句话

装一个 jar → 启动游戏 → 通过本地 MCP 走 `get_state → legal_actions → act` 循环打牌。
游戏里会有一个小光标跟着你的动作走，左上角小面板显示你正在想什么（人类在看你）。

## 1. 装它（人类做一次，约 5 分钟）

### 1.1 你需要有什么

| 组件 | 版本 | 怎么检查 |
| --- | --- | --- |
| 杀戮尖塔 | 2.3.4（`12-18-2022`） | Steam 库里有 `SlayTheSpire.exe` |
| ModTheSpire | 3.30.3 | 游戏目录里有 `ModTheSpire.jar`（或工坊 `646570/1605060445`） |
| BaseMod | 5.56.0 | 工坊 `646570/1605833019` |

只有**要自己编译**时才需要 JDK 8 + Maven 3.9；直接拿现成 `SpireLink.jar` 的话不用。

### 1.2 装 jar

```
<游戏目录>\mods\SpireLink.jar
```

然后**用 ModTheSpire 启动**，在模组列表里勾上 **BaseMod** 和 **SpireLink**。

### 1.3 自己编译（可选）

仓库不带游戏 jar，先往 `lib/` 放三个文件（`desktop-1.0.jar`、`ModTheSpire.jar`、`BaseMod.jar`，见 `lib/README.md`），然后：

```bat
scripts\build.bat                 rem 构建并装进 mods\
scripts\build.bat --no-install    rem 只构建
scripts\build.bat --check         rem 只检查工具链
```

> **别在游戏运行时构建**：jar 被占用会失败。

## 2. 启动、探活、配置

### 2.1 启动

```bat
scripts\run-game.bat        rem 经 ModTheSpire 启动（分离进程，脚本立刻返回）
scripts\start-game.bat      rem 启动 + 等 MCP 就绪，stdout 只吐一行 JSON
scripts\stop-game.bat       rem 关游戏，输出 {"stopped":true|false,...}
```

因为 `run-game.bat` 是分离进程，**不能靠脚本退出码判断游戏好了**，必须探活：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8731/health   # 期望 200
```

### 2.2 配置（改完要重启游戏）

`%LOCALAPPDATA%\ModTheSpire\SpireLink\config.properties`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `host` | `127.0.0.1` | 只允许环回，填别的会被强制改回 |
| `port` | `8731` | 被占用会明确报错，不会静默换端口 |
| `token` | 空 | 非空则每个请求要带 `Authorization: Bearer <token>` |
| `hud` / `hud_lines` | `true` / `4` | 左上角小面板，1–6 行 |
| `test_mode` | `false` | **true 才会有 `dev_*` 工具**（跳房间、造遭遇、发牌、999 血） |
| `speed` | `1.0` | 游戏倍速 |

> **最容易搞错的一件事**：`scripts\run-game.bat --test` 只是把窗口挪到副屏，**它不开 test_mode**。
> test_mode 只认配置文件里那行，而且**必须重启游戏**才生效。真实难度验证前请确认它是 `false`。

## 3. 连 MCP

端点：`http://127.0.0.1:8731/mcp`（JSON-RPC over HTTP / Streamable HTTP）。

```bash
# 1) initialize —— 响应头里有 Mcp-Session-Id，记下来
curl -s -D - -X POST http://127.0.0.1:8731/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"bigfish","version":"0"}}}'

# 2) notifications/initialized —— 返回 204 空 body，不要去 JSON.parse

# 3) 之后每个请求都带上会话头
curl -s -X POST http://127.0.0.1:8731/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'Mcp-Session-Id: <上一步拿到的 id>' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'
```

常驻 9 个工具：`get_state` `legal_actions` `act` `card_info` `glossary` `note_set` `note_get` `notes_list` `event_note`。
`test_mode=true` 时再多 10 个 `dev_*`。

另外三个**非 MCP** 端点：`GET /health`、`POST /hud/say`（往游戏里推一行字）、`GET /hud/driver`（谁在开车）。

## 4. 一局怎么打（核心循环）

```
loop:
  s = get_state(...)                        # 读局面
  if not s.meta.ready:               等 0.2~0.4s 再读       # 屏在切 / 动画 / 载入
  if s.meta.ui == "other" and s.meta.awaiting == "transition": 继续等
  la = legal_actions()                      # 这一拍真正能做的事
  pick = 从 la.actions 里挑一条
  r = act({type, ...payload, state_version: la.state_version, action_id: 唯一串})
  按 r.outcome 分支（见下表）
```

### 4.1 `act` 三种回执

| `outcome` | 含义 | 你该做什么 |
| --- | --- | --- |
| `applied` | 已生效 | 立刻 `get_state` 读新局 |
| `queued` | 已交给游戏，还没落地 | **只轮询 `get_state`**，绝对不要重发同一条 |
| `rejected` | 没执行 | 看 `code` 分支处理，别盲目重试 |

提交型动作（`continue_run` / `embark` / `abandon_*` / `confirm_abandon`）会返回 `settled:false`：
那不是失败，是「点击已交出去、世界正在过渡」，照常轮询等下一屏。

### 4.2 被拒了看什么

| `code` | 意思 | 下一步 |
| --- | --- | --- |
| `STALE_VERSION` | 你用的 `state_version` 过期 | 重新 `get_state`/`legal_actions`，用新版本重下 |
| `ILLEGAL_ACTION` | 这一拍没这个动作 | 从新的 `legal_actions` 里重挑，别硬试 |
| `NOT_READY` | 屏在动 / 动画没完 / 载入中 | 等，再读，不要连发 |
| `BUSY` | 上一条还在处理 | 轮询 `get_state`，不要并发 |
| `BAD_REQUEST` | 参数形状错 | 照回包里的模板改（`index` 要整数、动作参数**摊平**在 `act` 顶层） |

### 4.3 四个「不要」

1. 不要并发发 `act`（一条没落地就发下一条，会被 `BUSY` 顶回来）；
2. 不要重发 `queued` 的动作；
3. 不要把 `settled:false` 当失败；
4. 不要在没重读状态前重复同一个 `state_version`。

## 5. 便签 = 你的长期记忆

跨局保留，用来记「这只怪怎么打」「这张牌什么时候拿」。

```
note_set   {kind, id, text}     # kind ∈ event/potion/card/monster/relic/general
note_get   {kind, id}
notes_list {}
event_note {text, ...}          # 事件屏的快捷写法
```

- 一局结束时读 `postmortem`，看死因摘要，把结论写进便签。
- **省 token 的关键**：实体上的便签有 `note_state` 三个值 ——
  - `"none"`：没便签，`note:null`；
  - `"new"`：这一版第一次给你，带全文；
  - `"seen"`：已经给过了，`note:null`。
  只在 `new` 的时候读正文，`seen` 直接跳过（同一帧读 20 次也只有第 1 次带正文）。

## 6. 让人类看得见你在干嘛

- `POST /hud/say`，body `{"text":"...", "ttlMs":12000}`：往游戏左上角面板推一行想法（≤240 字）。
- 每 3–5 步说一句「我在等敌人回合」「这手先打痛击」就够了，别每步都刷。
- `GET /hud/driver`：查现在是谁在开车（多个客户端时用）。

## 7. 省 token 的姿势

| 做法 | 效果 |
| --- | --- |
| `get_state` 带 `include:["combat"]` | 只要战斗块（`combat/hand` 等），别每步都拉全量 |
| 牌组/地图只在需要时读 | `include:["deck"]` / `include:["map"]` |
| 便签只读 `note_state == "new"` | 一帧 8 个带便签的实体原本约 209 token，重复读等于白烧 |
| 一次 `act` 后必 `get_state`，中间不轮询 | 避免同一帧刷屏 |

## 8. 常见坑（照这个表对号入座）

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| `meta.ready` 一直 false | 屏在过渡/载入/黑屏 | 等 0.2–0.4s 再读，不要发 `act` |
| 老是 `STALE_VERSION` | 用了旧的 `state_version` | 每一拍都重新 `legal_actions` |
| 整回合一张牌不出、能量剩一堆 | 你自己定的出牌阈值太高（例如「评分 < 6 就不打」） | 能打就打：先算斩杀，再算格挡，最后把能量用光 |
| 只会从左到右出牌 | 评分打平后 tie-break 取了最左边 | 打平时按「先打易伤/虚弱，再打输出」排序，或加一点随机 |
| 便签每帧都重复出现 | 你在读 `seen` 的正文 | 看 `note_state`，只读 `new` |
| `act` 回 ok 但场面没变 | 那条是 `queued` | 轮询 `get_state`，别重发 |
| `tools/list` 里没有 `dev_*` | `test_mode=false` | 改配置 + 重启游戏（`run-game.bat --test` 不改这个） |
| 8731 连不上 | mod 没勾选 / 端口被占 / `token` 不匹配 | 看 `mods\spirelink-data\spirelink-debug.log` |
| 聊天窗口「看起来卡住很久」 | 你的驱动在一个 `run_code` 里跑了几十步，UI 不流式 | 靠 `/hud/say` 报进度，或把循环拆小 |
| `build.bat` 报缺 javac/mvn | 没设 `JAVA_HOME`，PATH 上也没 Maven | 装 Temurin 8 + Maven 3.9，或把它们放进 `tools\jdk8` / `tools\maven` |

## 9. 上手自检（15 秒）

1. `GET /health` → 200；
2. `tools/list` → 至少 9 个工具；
3. `get_state` → 有 `meta.state_version`，且连续两次读会递增；
4. 随便做一次 `act`（比如主菜单 `continue_run`）→ `outcome:"applied"`，`state_version` 变了；
5. `POST /hud/say` → 游戏左上角能看到你推的那句话。

五条都过，就可以开始打了。
