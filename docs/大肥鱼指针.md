# 大肥鱼指针（agent 的鼠标）

游戏里画一只「蓝发鱼娘」当指针，用来告诉看着屏幕的人：**agent 现在在点哪儿、正在干什么。**

它不是系统光标，也不是录制出来的鼠标轨迹——是游戏自己用 SpriteBatch 画的一张图。
它的**动作**不是随手定的：2026-11-02 晚上让人类实打实玩了一局 40 分钟，用 120 Hz 采样把
「人手怎么把指针挪过去」量下来，再照着这个形状写运动模型（见下面《人手是怎么动的》）。

![主菜单里的指针](img/fish-cursor-menu.png)

## 三条硬规矩

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | **只由游戏绘制，绝不碰系统鼠标** | 指针是游戏画的一张 sprite，窗口最小化/关闭它就跟着消失，不会漏到桌面上；真实鼠标和键盘一次都没被模拟过（全程只读写游戏内部状态）。 |
| 2 | **两个指针，两个主人** | 鱼只跟 agent 自己的动作目标走，**从不读** `InputHelper.mX/mY`（那是人类的鼠标），**也从不写**它。所以人类甩鼠标时鱼不会乱跑，agent 干活时人类的箭头也不动。 |
| 3 | **只在游戏窗口内出现** | 挂在 `AbstractDungeon.render`（局内）和 `MainMenuScreen.render`（主菜单/选人）两个后置钩子上，别的地方一张都不画。 |

## 六种表情，按场景自动切换

素材是用户提供的一整套贴纸，只启用其中 6 张（其余对角线/文本选择等在这游戏里用不上）：

| 贴图 | 什么时候出现 | 触发点 |
|---|---|---|
| `normal` 正常 | 停在 agent 最后操作的那个点上 | 动作结束后落地、按下松开、静置 0.9 秒 |
| `hover` 悬停 | **正朝目标飞过去**（还没到） | 滑行中；人也是这样，路上是「移动」而不是「已经在那了」 |
| `click` 点击 | **落地之后**那一下 | 滑行结束 + 60 ms（手指落下的时间）起 0.9 秒 |
| `drag` 拖动 | 正在卡牌选择格里挑牌 | 上一次动作是 `choose_grid_cards`/`choose_hand_cards`，或选择格里已有勾选 |
| `busy` 忙碌 | agent 在等模型/请求在途 | HUD 推出「正在琢磨怎么打…」这类等待文案时 |
| `help` 帮助 | 动作被拒、或模组还没就绪 | 拒绝结果 / 「还没连上」文案；1.6 秒后自动收起（未就绪时一直挂着） |

优先级：**help > busy > hover（还在路上） > click/drag > normal**（出问题最要紧，其次是正在赶路，再次是刚做完什么）。

![局内：打出一张牌，鱼从上一张牌滑到手牌上](img/fish-glide-frames.png)

图里那句「打出手牌《打击》」就是鱼脚下的小字，和左上角 HUD 的文案同源（`AgentHud.action` 一次调用喂两处），不会出现「HUD 说 A、鱼说 B」。

## 人手是怎么动的（2026-11-02 实测）

采集方式：`内部验收脚本（未随仓库发布）`（120 Hz 读 `GetCursorPos`/`GetAsyncKeyState`，每次左键存一张
`PrintWindow` 截图，每 5 秒记一次模组 `get_state`）。样本是用户本人打的一整局：
**铁甲战士，1 → 33 层（第二幕），40.7 分钟，死在 33 层**，共 102,397 个采样点。

| 量的是什么 | p10 / 中位 / p90 | 说明 |
|---|---|---|
| 「停 → 停」一次移动的距离 | 47 / **339** / 698 px | 大部分是从手牌挪到敌人、或反过来 |
| 一次移动的时长 | 0.23 / **0.51** / 1.08 s | 含最后那截慢慢蹭过去的尾巴 |
| 峰值速度 | 347 / **1965** / 3765 px/s | 手腕甩起来很快，但只有中间一瞬 |
| 路径直线度（直线距离/实际路程） | 0.48 / **0.98** / 1.01 | 几乎是直线，人手不做绕路 |
| 峰值出现在第几成时长 | 20% / **41%** / 71% | 先快后慢：加速段短，减速段长 |
| 停顿 | 0.43 s 中位；>1 s 有 408 次，>3 s 有 106 次 | 38.7% 的时间指针是停着的 |
| 点击前在落点 6 px 内待了多久 | 0.00 / **0.08** / 0.58 s | 到了就点，不磨蹭 |
| 按住时长 | 0.06 / **0.15** / 1.23 s | 其中 82 次超过 0.8 s —— 是**拖牌**，不是点 |
| 点击后 300 ms 内移开多远 | 46 px（中位） | 点完立刻走人，不赖在牌上 |

两条能直接看出「人在想事」的：

- 停的时间**集中在手牌区**（屏幕下三分之一 7.6 分钟 > 中间区域 5.3 分钟）——读牌是停在牌上读的，
  而不是把指针悬在敌人身上。
- Fitts 拟合：`T ≈ 0.206 + 0.135·log2(D/40 + 1)` 秒（r=0.35，策略差异大，只看趋势）。

## 鱼现在怎么动

`AgentCursor` 里没有「瞬移」这个词，只有一次带时长的手部动作：

1. **时长看距离**：`T = 0.12 + 0.11·log2(D/40+1)`，钳在 0.12–0.60 s。340 px 约 0.47 s，
   和人类的 0.51 s 对得上；比人略快一点，因为 agent 一两秒就一个动作，太慢会追不上。
2. **速度走钟形**：最小 jerk 曲线，再做一个 `u^0.85` 的时间弯曲——人手在前四分之一时间里
   已经走完 18% 的路，纯最小 jerk 只有 10%，弯一下才像。
3. **落地才按**：滑行结束 → 等 60 ms → 按下（贴图缩到 0.91，100 ms 弹回）→ `click` 脸 0.9 s。
   动作在游戏里其实早就生效了，这里补的是「手是怎么落下去的」。
4. **点完就走**：落地 0.5 s 后，朝「家」（屏幕下方正中）的方向滑开 22 px，0.45 s 滑完。
   人类点完 300 ms 内平均已经移开 46 px，鱼不动就会一直挡着那张牌。
5. **静止也在动**：站着时 0.9 px / 0.7 px 两个不同频率的正弦抖动——真人手放桌上也有 1–3 px 的抖。

![人手的累计位移（蓝） vs 鱼实测的累计位移（红）](img/fish-speed-profile.png)

蓝线是那 230 次 480–720 px 的真实移动，红线是鱼一次 604 px 滑行的逐帧实测：
两条 S 曲线基本重合，鱼的峰值速度出现在 44% 处（人类中位 41%）。

## 位置是怎么来的

目标坐标是在**动作执行之前**量的：

- `play_card` → 按 `payload.uuid` 在手里找那张牌，取 `card.hb.cX/cY`
- `choose_map_node` → `AbstractDungeon.map[y][x].hb`
- `end_turn` → 结束回合按钮（`hb` 是 private，走反射）
- `choose_option` → 事件选项按钮 `LargeDialogOptionButton.hb`
- `take_reward` → `CombatRewardScreen.rewards[i].hb`
- `choose_character` / `embark` → 选人界面的角色卡与确认按钮
- `open_mode_select` / `continue_run` / `abandon_run` → 主菜单按钮（按 `MenuButton.ClickResult` 找）。**主菜单那一屏只会出现一套按钮**：有存档 =「继续上次的一局 / 放弃存档」，无存档 =「单人游戏（`open_mode_select`）」——两套坐标不同，所以按 `ClickResult` 现找、不写死（issue #67）

必须先量：牌打出去就从手里没了、地图选完节点就重建，事后再找那个 hitbox 早就没了。
量到的是**游戏坐标**，鱼画在目标上方偏右 74/44（× 分辨率系数）像素处，目标点上再画一个浅黄十字（+），
所以「鱼在哪」和「点在哪」是两件事，不会被鱼身子挡住。

还没做过任何动作时（比如刚进主菜单），鱼停在屏幕下方正中的「家」位置，半透明——看得见，但不碍事。

## 每个接口动作都有一只手

硬要求：**接口能做的每个动作，屏幕上都看得见是谁点的。** 不是「大部分动作」，是全部——
`act` 的每一种 `type` 都要把鱼挪到人类会去点的那个东西上，落地、按下、停 0.9 秒，
和真的操作一模一样。没有「后台静默生效」的动作。

| 动作 | 鱼去哪儿 |
|---|---|
| `open_mode_select` / `continue_run` / `abandon_run` | 主菜单对应的那一行。**按存档二选一**：有存档只有「继续 / 放弃存档」两行，无存档只有「单人游戏（`open_mode_select`）」那一行；提示「点了哪一行」的口径不变 |
| `choose_mode` | 标准 / 每日 / 自定 面板 |
| `choose_character` | 四张角色卡里被选中的那张 |
| `choose_ascension` | 进阶难度的左右箭头（往哪边走点哪边） |
| `embark` | 右下角「启程」 |
| `back` / `confirm_abandon` / `cancel_abandon` | 返回键 / 确认框的是与否 |
| `dismiss_tip` | 教程弹窗的「知道了」 |
| `abandon_mid_run` | 右上角齿轮（真人放弃一局也是从这儿进的） |
| `choose_neow_reward` / `choose_option` | 涅奥、事件的那个选项按钮 |
| `event_continue` | 事件对话框 |
| `choose_map_node` | 地图上那个节点 |
| `play_card` | 手里那张牌（按 uuid 找，不按序号猜） |
| `end_turn` | 右下「结束回合」 |
| `use_potion` / `discard_potion` | 顶部那一格药水 |
| `take_reward` | 奖励列表里那一条 |
| `take_card` / `skip_card` | 选牌界面里的那张牌 / 「跳过」 |
| `claim_relic` / `skip_relic` | Boss 遗物 / 它的跳过 |
| `rest` / `smith` / `lift` / `toke` | 篝火那几个按钮（休息 / 锻造 / 举重 / 烧牌） |
| `open_shop` / `buy` / `purge_card` / `leave` | 商人 / 那件商品 / 净化服务 / 离开 |
| `open_chest` | 宝箱 |
| `choose_grid_cards` / `confirm_grid` / `cancel_grid` | 网格里的牌 / 确认 / 取消 |
| `choose_hand_cards` / `confirm_hand_select` / `cancel_hand_select` | 手里的牌 / 按钮 |
| `choose_match_card` | 翻牌小游戏的那张牌 |
| `proceed` | 右下「继续」 |

唯一的例外是 `verify_*`：那是内部复查（拿不准时再读一次状态），不改游戏，所以鱼不动。
它们也不对 agent 公布。

### 顺序：手先到，游戏才变

一条容易做反的细节：**动作要等手到了才执行。**

游戏是在 `act` 被调用的那一瞬间就把事情做掉的（牌已经打出去、奖励已经进包），
如果指针是事后才飞过去，屏幕上永远是「动画先播，鼠标后到」——看着就像卡了一拍。

所以 `act` 的流程是：

1. 在**请求线程**上算出目标、放飞指针；
2. 等指针滑到（`AgentCursor.awaitArrival`，上限 0.7 s，实测 0.28–0.62 s）；
3. 才把动作交给主线程执行；
4. 动作成功 → 按下动画（贴图缩 0.91，100 ms）→ `click` 脸。

第 2 步必须在请求线程上等，**不能**在主线程上等：滑行是主线程每帧驱动的，
主线程要是被 `sleep` 卡住，等的那 0.6 秒里指针一格都不动，等完了才「嗖」地窜过去——
正好是最难看的那种延迟。

### 看牌也算动作

「看一眼」在屏幕上也是要动的：agent 读哪份牌，人就得看见它在读哪份。

| 调用 | 屏幕上发生什么 |
|---|---|
| `card_info{uuid}` | 手牌里的那张牌被抬起来（游戏自己的 hover 动画，卡面放大、出关键词提示），鱼先走到那张牌上；不在手里的牌走右侧详情面板 |
| `card_info{uuid, upgraded:true}` | 大图弹窗显示**升级后**那张牌（原版 `SingleCardViewPopup`，底部还有「看升级版」勾选框），3.2 秒自动关 |
| `get_state{include:["deck"]}` | 鱼走到右上角的牌组按钮，牌组列表打开，4 秒后自动关 |
| `get_state{include:["discard_pile"]}` | 鱼走到左下（弃牌堆）按钮，弃牌堆打开，4 秒后自动关 |
| `get_state{include:["exhaust_pile"]}` | 同上，消耗堆 |
| `get_state{include:["draw_pile"]}` | 同上，抽牌堆 |

三次「看」都是 `先走过去再打开`（`DeckPeek.request` 里算一次滑行时长，`tick()` 到点才开），

关的时候也一样：牌表到期不是直接消失，鱼先走到左下角「返回」，到点才真正关屏
（`peek_deck: 去点返回（auto-close after 4s，600ms）` → `close`）。
关屏走「恢复打开前的 screen + isScreenUp」，所以回到的就是原来那一屏。

![鱼落在「返回」上，牌组刚关掉](img/fish-click-back.png)

![看升级效果：放血 -> 放血+](img/fish-upgrade-preview.png)

不是先弹窗再补个指针。牌表打开期间 `meta.ui` 仍然报打开之前那一屏，
`legal_actions` 也照旧——看牌永远不是决策点，任何真动作会先把牌表关掉。

### 怎么确认它真的动了

每个动作都会在调试日志里留一行：

```
cursor: play_card -> 603,15 到位 602ms
cursor: end_turn -> 1640,210 到位 616ms
cursor: choose_neow_reward -> 无目标 到位 0ms
```

坐标是游戏坐标（左下角原点）。`无目标` 只在两种情况下出现：`verify_*`，或者
那个 hitbox 还没排版好——比如涅奥第一个选项的 hitbox 初值是 `-9554,-9960`，这种位置
会被判成无效（超出窗口 64 px 以外一律不认），鱼原地不动，而不是一头飞出屏幕。

## 分辨率

游戏窗口多大，`Settings.WIDTH/HEIGHT` 就是多大。所以**所有尺寸都乘一个 `H/1080` 的系数**
（`uiScale()`）：精灵、偏移、十字、抖开的那 22 px、滑行时长用的距离，全都跟着走。
720p 下鱼是 99 px，1080p 下 148 px，4K 下 296 px——看上去一样大，手感一样。

### 实测：720p 与 1080p

同一台机器、同一个 jar，把 `info.displayconfig` 从 `1920×1080` 改成 `1280×720` 重启后：

| 动作 | 1080p 日志 | 720p 日志 | 比值 |
|---|---|---|---|
| `proceed`（「前进」按钮） | `1670,320` | `1113,213` | 0.667 |
| `choose_map_node`（第 3 列怪） | `565,395` | `377,263` | 0.667 |
| `play_card`（手牌第二张） | `603,15` | `402,10` | 0.667 |

坐标整体就是 `×0.667` —— 因为 `Settings.WIDTH/HEIGHT` 跟着窗口走，
命中框自动就落在这个空间里；鱼的大小也乘同一个系数（`148×0.5×0.667 ≈ 49 px`），
720p 截图里鱼正好落在「打击+」那张牌上，和 1080p 的比例一致。

![720p：鱼落在手牌上，字幕在下方](img/fish-720p.png)

注意：**窗口模式下游戏不给你 1920×1080**。分辨率来自 `<游戏目录>\info.displayconfig`
（游戏「设定」里改分辨率就写这个文件），而 `CardCrawlGame.resize()` 反编译出来是空的
（`0: return`），运行中改窗口大小它不会重排：画面会缩在左下角，右边一片黑。
要换分辨率就改 `info.displayconfig` 再重启，或者用游戏里的「全屏」。

## 配置

`%LOCALAPPDATA%\ModTheSpire\SpireLink\config.properties`：

```properties
# 关掉鱼（true/false）
cursor=true
# 大小：1.0 = 148px（1080p 下），默认 0.5（约 74px）
cursor_scale=0.5
```

改完重启游戏生效。启动日志里会有一行：`大肥鱼指针=开，缩放=0.5`，加载贴图时还会打一条
`指针贴图已加载: spirelink/ui/cursor/normal.png`。

## 想再量一次人手

量人手的采集脚本没有随仓库发布（它们只是本机的采样工具，还会带出桌面信息）。做法是：
用 `scripts\run-game.bat` 开一局，另外挂三个只读程序 —— 一个 120 Hz 记录 `GetCursorPos` /
`GetAsyncKeyState`，一个定时轮询 `get_state` 落盘，一个把 MCP 回包存档；打完统计位移—时间曲线的分位数（即上表那几列）。

## 已知边界

- 贴图缺失/损坏时**静默降级**：不画鱼，其余功能全不受影响（有 `指针贴图缺失` 警告日志）。
- 一面屏只有一只鱼：它表达「最近一次动作」，不是动作队列。动作比滑行还快时，鱼会从当前位置直接改瞄新目标（和人一样），不会排队。
- 主菜单的「单人游戏 / 继续」已经接了坐标；「设定 / 百科大全」这类纯浏览按钮还没接。
